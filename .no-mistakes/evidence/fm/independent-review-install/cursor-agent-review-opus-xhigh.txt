## Serious issues

**1. Even-length median picks the wrong pair of middle values (critical).**

```8:8:src/stats.py
    return (s[n // 2] + s[n // 2 + 1]) / 2
```

For an even-length list, the two middle values are at positions `n//2 - 1` and `n//2`. The code uses `n//2` and `n//2 + 1`, one position too far to the right.
- `median([1, 2, 3, 4])` returns 3.5 instead of 2.5. It's wrong but doesn't raise an error, so the bad value flows into whatever uses it.
- `median([1, 2])` raises `IndexError` because position 2 doesn't exist.
- Odd-length lists are fine.

Fix:

```python
return (s[n // 2 - 1] + s[n // 2]) / 2
```

Or use the standard library's `statistics.median`, which is already tested.

**2. No tests at all (serious process gap).** The repo contains only `src/stats.py`. Even one even-length test case would have caught issue 1. Minimum cases to add:
- `median([3]) == 3`
- `median([3, 1, 2]) == 2`
- `median([1, 2]) == 1.5`
- `median([4, 1, 3, 2]) == 2.5` (unsorted, even length)
- `mean([1, 2, 3, 4]) == 2.5`
- Empty input raises a clear error for both functions.

## Minor issues (not blocking)

- **Empty input gives confusing errors.** `median([])` raises `IndexError` and `mean([])` raises `ZeroDivisionError`. The docstring says the list must be non-empty, so this is allowed. Still, a `ValueError("values must be non-empty")` would be clearer to callers.
- **`mean` doesn't work on generators.** `sum()` uses up the generator, then `len()` raises `TypeError`. `median` handles generators because it calls `sorted()` first. The stated contract is lists, so this is low risk.
- `mean` has no docstring, unlike `median`.
